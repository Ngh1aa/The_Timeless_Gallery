# FinFlow Visual Direction — Human-made Institutional Settlement

## Intent

Redesign FinFlow away from generic AI-generated fintech/SaaS composition while preserving the project's strongest domain-native idea: the inspectable multi-rail route.

Reference input: Column-style institutional banking surface supplied by the project owner. The reference is used for principles, not copied surface-for-surface.

## Design DNA

**Operational · Editorial · Human-made**

The page should feel like a financial operating surface with editorial restraint, not a collection of generated SaaS cards.

## Primary signature

**Halftone settlement atlas + floating route desk**

If the logo disappears, FinFlow should still be recognizable through:
- dotted global settlement field;
- a visible transaction instruction;
- one switching/orchestration point;
- five persistent rail states;
- a selected route moving across the field.

## KEEP

- Five-rail mental model.
- Route Inspector interaction and scenario switching.
- Inter typography for reliable HTML → Figma conversion.
- Explicit selected / available / unavailable states.
- Three-section narrative: hero → mechanism → operations/conversion.
- Honest prototype/evidence boundaries.

## REVISE

### Hero
From:
- dark SaaS hero;
- eyebrow + large slogan + stats + dashboard card;
- too many simultaneous emphasis devices.

To:
- near-white institutional canvas;
- direct product language;
- global dotted settlement field;
- one floating operating desk;
- rail names as a quiet system index.

### Typography
Use Inter with editorial restraint:
- display: 50–68px / 600;
- secondary display lines may use 400 weight;
- body 14–17px;
- technical labels 8–12px;
- avoid excessive uppercase and letter spacing.

### Color
- institutional indigo for primary text/action;
- seafoam only for data/availability;
- cobalt for route selection;
- warm orange only as packet/high-signal punctuation;
- near-white / pure-white surface stack.

### Components
Replace repeated cards/badges with:
- ledger rows;
- settlement slips;
- trace rows;
- data fields;
- border-led grouping.

### Motion
Motion follows state:
1. semantic rail state changes;
2. selected path draws;
3. transaction packet moves.

No glow-heavy ambient animation.

## REMOVE

- Generic three-stat hero strip.
- Repeated section-key decoration.
- Repeated “01 / 02 / 03” card grammar when numbers do not add meaning.
- Glow as a visual identity.
- Dense dark dashboard framing across the whole page.
- Bento-style outcome card walls.
- Marketing slogans that sound symmetrical but add little product information.

## Page-role composition

### Hero / orientation
Question: What does FinFlow do and where does it sit?
Composition: text left, halftone settlement field across the canvas, interactive transaction desk right.

### Mechanism / comprehension
Question: What happens from instruction to payout?
Composition: vertical six-step ledger left, large inspector right, three plain-language operating principles below.

### Operations / decision
Question: What remains visible and what should I do next?
Composition: four operating ledger rows, dark settlement trace as the single high-contrast object, compact workflow-demo form.

## Responsive transformation

Desktop:
- split hero;
- network visualization remains spatial;
- mechanism is ledger + inspector.

Mobile:
- copy precedes product surface;
- route network becomes a vertical state stack;
- no hover-only content;
- mechanism rail line can collapse because the step ledger already preserves sequence;
- settlement trace precedes conversion.

## Anti-template test

The redesign fails if:
- swapping the FinFlow logo and copy makes the page believable as an AI, HR or analytics SaaS;
- the dotted atlas is purely decorative and no longer connects to route behavior;
- more than one section becomes a repeated card grid;
- state meaning depends on glow or motion;
- typography falls back to uniform 600/700 weight everywhere.

## Reference adaptation boundary

The supplied Column reference contributes:
- light institutional canvas;
- restrained navy/green data roles;
- floating product objects;
- dotted global-connectivity field;
- editorial type contrast;
- limited shadow/elevation.

FinFlow deliberately does not copy:
- Column wording;
- customer-logo proof;
- FDIC/regulatory claims;
- exact world map;
- exact product card;
- exact typeface;
- exact navigation or component shapes.
