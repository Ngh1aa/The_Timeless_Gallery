Why this matters

The interaction demonstrates consistency, not routing intelligence.

The scenarios are illustrative. The prototype does not claim the exact rules a production routing engine would use; it demonstrates how route state could remain inspectable across different payout modes.

ComprehensionSame grammar every time

Users do not need to relearn the interface when the payout mode changes.

AccessibilityLabels survive without color

Every rail exposes a textual state, so the distinction is not color-only.

Evidence boundarySimulation is explicit

The UI showcases a concept state model, not production decision criteria.
