User Journey

The buyer journey is modeled as six evaluation stages. Each stage pairs a user question with the interface response, evidence shown and risk if the page fails.

Evaluation journey

From “Is this relevant?” to “Show me how it fits my workflow.”

Stage

Wallet / Bank / Cash scenario switcher.

04 · Inspect30–60 sec
How does a payout move?
Six-step mechanism with synchronized inspector.
Receive → Analyze → Route → Settle → Payout.
Mechanism remains a black box.
05 · Trust60–90 sec
What makes this credible?
Operational outcomes, trace language and explicit evidence boundaries.
Inspectable state instead of fake proof.
Buyer distrusts marketing claims.
06 · Convert90 sec+
What do I do next?
Workflow-specific demo request.
“Bring one payout journey.”
Generic CTA loses context.
Experience principles

Rules that keep the journey coherent.

Principle 01Show state before claims

Whenever possible, let the interface demonstrate route selection rather than narrate “intelligence.”

Principle 02Progressive technical depth

Start with buyer-level language, then reveal operational detail through interaction.

Principle 03Preserve the mental model

Use the same route grammar in hero, mechanism, mobile and ad creative.

Validation status

This journey is a design hypothesis informed by the product brief and reference research. It has not been validated through user interviews or usability sessions; frame 12 defines the validation plan.
